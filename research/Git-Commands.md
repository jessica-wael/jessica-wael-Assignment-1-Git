##### **# Git Command Deep-Dive****--------------------------------**&#x20;## git squashبيدمج أكتر من commit في commit واحد.السيناريو: اشتغلت على فيتشر وطلعلك 8 commits صغيرة زي "wip" و"fix typo". قبل الـ Pull Request بتدمجهم في commit واحد نضيف\*\* الامر :git rebase -i HEAD\~8\# أوgit merge --squash feature\---&#x20;## git merge vs git rebase\*\*merge: بيدمج فرعين ويعمل merge commit، والتاريخ بيفضل زي ما هو. \*\*الامر:git checkout maingit merge feature/login\*\*rebase: بينقل commits بتاعتك فوق آخر نسخة من main، فالتاريخ بيبقى خط مستقيم\*\*السيناريو:  فرعك اتأخر عن main، فبتعمل rebase عشان تاخد آخر التحديثات من غير merge commit زيادة.\*\*الامر:git checkout feature/cartgit rebase mainالمفروض ماتعملش rebase على فرع غيرك بيشتغل عليه.\---&#x20;git help ##\*\*الشرح:\*\* بيفتح دليل أي أمر.\*\*السيناريو:  نسيت options بتاعة `git log`، فبتفتح الدليل من غير ما تخرج من الترمنال.\*\*الأمر:git help log\---&#x20;git cherry-pick ##\*\*الشرح:   بياخد commit واحد معين وينسخه لفرع تاني.\*\*السيناريو:  اتصلح bug في فرع dev، ومحتاج نفس الإصلاح في production من غير باقي الفيتشرز اللي لسه مخلصتش.\*\*الأمر:git cherry-pick <commit-hash>\---&#x20;git clean ##\*\*الشرح:  بيمسح الملفات غير المتتبعة (untracked).\*\*السيناريو:  بعد الـ build فضلت ملفات مؤقتة في الفولدر وعايز تنضفه.\*\*الأوامر:git clean -n    # للمعاينهgit clean -fd   # مسح فعلي\---git grep ##\*\*الشرح:  بيدور على نص جوه ملفات المشروع.\*\*السيناريو:  عايز تعرف دالة `CalculateTotal` مستخدمة فين في المشروع كله.\*\*الأمر:git grep "CalculateTotal"\---&#x20;git blame ##\*\*الشرح:  بيعرض مين آخر واحد عدّل كل سطر وإمتى.\*\*السيناريو:  لقيت سطر كود غريب. بتعرف مين كتبه وفي أنهي commit، عشان تفهم السبب أو تسأل صاحبه.\*\*الأمر: git blame file.cs\---git bisect ##\*\*الشرح:  بيدور على أول commit كسر الشغل باستخدام البحث الثنائي.\*\*السيناريو:  فيتشر كان شغال من أسبوعين وبقى بايظ، والـ commits كتير. بتحدد commit سليم وcommit بايظ، وgit بيقسم المسافة لحد ما يلاقي المتسبب.\*\*الأوامر:git bisect startgit bisect badgit bisect good <commit-hash>\---git shortlog ##\*\*الشرح:  بيلخص الـ commits حسب كل شخص.\*\*السيناريو:  آخر الـ sprint محتاج تقرير بكل واحد عمل كام commit، أو material للـ release notes.\*\*الأمر:git shortlog -sn\---&#x20;git prune ##\*\*الشرح:  بيمسح الكائنات اليتيمة (unreachable) من قاعدة بيانات git.\*\*السيناريو:  بعد ما مسحت فروع وعملت rebase كتير، حجم الـ repo زاد. بتنضّفه عشان يخف.\*\*الأمر: git prune\---&#x20;git worktree ##\*\*الشرح:  بيفتح فولدر تاني لفرع تاني من نفس الـ repo.\*\*السيناريو:  شغال على فيتشر وجالك bug عاجل في main. بدل stash وتبديل الفروع، بتفتح فولدر جديد وتشتغل في الاتنين مع بعض.\*\*الأمر:git worktree add ../hotfix main\---&#x20;git verify-commit ##\*\*الشرح:  بيتأكد إن الـ commit موقّع بـ GPG.\*\*السيناريو:  في مشروع حساس، بتتأكد إن الـ commit فعلاً من المطور الموثوق مش حد منتحل.\*\*الأمر: git verify-commit <commit-hash>\---git filter-repo ##\*\*الشرح:  بيعدّل التاريخ كله، فيمسح ملف أو يغيّر حاجة من كل الـ commits.\*\*السيناريو:  حطيت password أو ملف ضخم بالغلط في الـ repo. بتشيله من كل التاريخ، وبعدها تغيّر الباسورد وتعمل force push.\*\*الأمر: git filter-repo --path secrets.txt --invert-paths
